# 22 — Synteny + Functional Annotation Browser Integration Plan

Goal: surface the gene-anchored synteny between the **lean** and **siscowet**
ecotypes ([`code/21.1-gene-anchored-synteny.Rmd`](21.1-gene-anchored-synteny.Rmd)),
together with per-gene functional annotation
([`code/20.1-liftoff-annotation.Rmd`](20.1-liftoff-annotation.Rmd)), inside the
interactive genome browsers that ship with the project website.

---

## 1. What we have to work with

### Browsers on the site (both anchored on the **reference** SaNama_1.0 coordinate system)
- **IGV.js** — `genome-browser/` — tracks configured in
  [`genome-browser/js/config.js`](../genome-browser/js/config.js), data staged in
  `genome-browser/data/{annotations,pav,methylation}/`, generated by
  `genome-browser/prepare_data.py`. Reference chromosomes are `NC_052307.1 … NC_052348.1`.
- **JBrowse 2** (v3.6.2) — `jbrowse/` — tracks in
  [`jbrowse/config.json`](../jbrowse/config.json), data in `jbrowse/data/lake-trout/`.
  One assembly declared (`SaNama_1.0`), FeatureTracks fed by BED adapters.
- Both are linked from [`index.qmd`](../index.qmd) §"Interactive Genome Browsers".

### Synteny outputs — `output/21.1-gene-anchored-synteny/` (large; hosted on Gannet, not committed)
- `synteny_blocks.tsv` — block-level: `comparison, block, n_anchors, chr_a, chr_b, orientation`.
  Comparisons: `reference_vs_lean` (1,897), `reference_vs_siscowet` (1,966), `lean_vs_siscowet` (4,113).
- `contig_to_chromosome.tsv` — `comparison, chr_a, chr_b, anchors` (contig→chr assignment).
- `lean_sisco.collinearity`, `ref_lean.collinearity`, `ref_sisco.collinearity` — MCScanX anchor pairs (gene-ID based).
- `*.gff` (MCScanX gene-position format), `*.blast`, `*.html` dotplots.
- `lean.purged.fa` / `siscowet.purged.fa` (+ `.fai`) — purged ecotype assemblies.
- `{lean,siscowet}.purged.liftoff.genes.bed` — gene positions in **ecotype** coords.

### Functional annotation — `output/20.1-liftoff-annotation/`
- `{lean,siscowet}.liftoff.gene_function_table.tsv` — **the bridge table**. Each gene carries
  BOTH ecotype coords (`eco_chrom/start/end/strand`) AND reference coords
  (`chrom/start/end/strand`), plus `symbol`, `geneid`, `biotype`, `product`,
  `n_go`, `go_bp/mf/cc`, `go_terms`.

### Key coordinate facts / gotchas
- Liftoff assigns the **same reference `gene-LOC…` ID** to orthologs across assemblies →
  synteny anchors are gene-ID identity, and the function table maps every ecotype gene back
  to a reference locus. This is what lets us project ecotype/synteny data onto reference coords.
- MCScanX required sanitized chr names (e.g. `NC_052308.1` → `rfNC0523081`,
  `ptg000001l_1` → `lnptg000001l1`). Any reference-anchored track must **un-sanitize** back to
  `NC_0523xx.1` to line up with the browser's sequence.
- Liftoff `-copies` appends `_N` (e.g. `gene-LOC120041454_1`); strip for base-ID joins.

## 2. Two integration paths (do both, phased)

### Path A — Reference-anchored tracks (fits **both** existing browsers, low effort)
Project synteny + annotation onto the reference genome so they appear as ordinary tracks
alongside the existing PAV/methylation tracks. No new assembly hosting required.

**A1. Functionally-annotated gene track (GFF3).**
Replace/augment the current `genes.bed` with a GFF3 built from
`*.gene_function_table.tsv` so JBrowse's feature-detail panel shows `symbol`, `product`,
`biotype`, and GO terms on click. (IGV.js shows the `Name`; put `symbol | product` there.)
One track per ecotype is unnecessary here — reference coords are shared — so emit a single
`genes_annotated.gff3` keyed on reference locus, with columns for whether the gene is
present/expanded in lean vs siscowet (from `is_named` / copy counts).

**A2. Synteny-block tracks (BED, one per ecotype).**
From `synteny_blocks.tsv` (`reference_vs_lean`, `reference_vs_siscowet`) + the function
table, compute each block's **reference footprint** (min/max reference coord of its anchor
genes) and emit a BED feature: name = ecotype contig (`chr_a`), score = `n_anchors`,
strand = `orientation` (`minus` = inversion relative to reference). Result:
`synteny_lean_blocks.bed`, `synteny_siscowet_blocks.bed`. Reviewers can see, at any reference
locus, which ecotype contig maps there and whether it is inverted.

**A3. Cross-ecotype synteny / breakpoint track (BED, optional).**
From `lean_vs_siscowet` blocks joined through the function table's reference coords, mark
reference intervals where lean and siscowet contigs **disagree** (block boundaries not shared)
— candidate structural-rearrangement breakpoints. Colored highlight track.

Wire-up:
- IGV.js: add entries to `TRACK_CONFIGS` + `DEFAULT_TRACKS` in `js/config.js`, stage files
  under `genome-browser/data/synteny/` and `.../annotations/`.
- JBrowse: add FeatureTracks (BedAdapter / Gff3Adapter) under a new `category: ["Synteny"]`
  in `config.json`, stage files under `jbrowse/data/lake-trout/`.

### Path B — JBrowse 2 Linear Synteny View (native comparative view, higher effort)
JBrowse 2 natively renders two assemblies stacked with connecting ribbons. This is the
"real" synteny experience (inversions, translocations, contig fragmentation visible directly).

**B1. Declare ecotype assemblies** in `config.json` (`lean_purged`, `siscowet_purged`) with
IndexedFastaAdapter pointing at the Gannet-hosted `*.purged.fa` + `.fai`.

**B2. Add synteny tracks** using `MCScanAnchorsAdapter` (or `MCScanSimpleAnchorsAdapter`),
which needs: the anchors file + the two gene-position BEDs (4-col `chr start end name`).
Convert `*.collinearity` → `.anchors` and the MCScanX `*.gff` → JBrowse-style BED for each of
the three comparisons (`ref↔lean`, `ref↔sisco`, `lean↔sisco`). PAF via `PAFAdapter` is an
alternative if we'd rather derive alignments from minimap2 output already in the intermediate dirs.

**B3. Ship a saved Linear Synteny session** (JBrowse session/URL config) so the browser link
opens directly into lean-vs-siscowet with the annotated-gene tracks loaded on each row —
functional annotation and synteny visible together.

## 3. Deliverables / implementation steps

1. **`code/22-synteny-browser-tracks.py`** (or `.Rmd`) — the data-prep script:
   - Load both `gene_function_table.tsv`; build reference-coord annotated GFF3 (A1).
   - Build reference-anchored synteny-block BEDs from `synteny_blocks.tsv` (A2) + breakpoint BED (A3).
   - Un-sanitize chr names back to `NC_0523xx.1`; strip `_N` copy suffixes; sort + bgzip/tabix
     the GFF3 for JBrowse.
   - Convert `*.collinearity` + `*.gff` → `.anchors` + 4-col BEDs for Path B.
   - Write `.md5` sidecars to match repo convention.
2. **Stage data**: copy small outputs into `genome-browser/data/synteny/` and
   `jbrowse/data/lake-trout/`; push large FASTAs to Gannet and reference by URL.
3. **Config edits**: `genome-browser/js/config.js` (+ `prepare_data.py` so it's reproducible)
   and `jbrowse/config.json` (Path A tracks now; Path B assemblies + synteny tracks next).
4. **Website copy**: update [`index.qmd`](../index.qmd) §"Interactive Genome Browsers" and
   `README.md` to describe the synteny/annotation tracks and the JBrowse synteny view.
5. **Docs**: extend `genome-browser/README.md` track tables; note this plan's provenance in
   [`code/21.1-gene-anchored-synteny.Rmd`](21.1-gene-anchored-synteny.Rmd).

## 4. Suggested sequencing
- **Phase 1 (Path A) — ✅ DONE.** annotated gene GFF3 + two synteny-block BEDs in both browsers.
  Implemented by [`code/22-synteny-browser-tracks.py`](22-synteny-browser-tracks.py); outputs in
  `output/22-synteny-browser-tracks/`, staged into `genome-browser/data/synteny/` and
  `jbrowse/data/lake-trout/`; wired into `genome-browser/js/config.js` and `jbrowse/config.json`.
  - `genes_annotated.gff3` — 46,359 reference genes, 45,069 with symbol/product/biotype/GO +
    `ecotypes=` presence tag.
  - `synteny_lean_blocks.bed` — 1,897 blocks; `synteny_siscowet_blocks.bed` — 1,966 blocks
    (name = `ecotype:contig|block#|n=anchors`, strand = orientation).
- **Phase 2 (Path B) — ✅ DONE (lean↔siscowet).** JBrowse 2 Linear Synteny View data.
  Implemented by [`code/22.2-jbrowse-synteny-view.py`](22.2-jbrowse-synteny-view.py):
  converts `lean_sisco.collinearity` → `lean_siscowet.anchors` (4,113 blocks / 77,628 anchor
  pairs) and the combined `lean_sisco.gff` → `lean_purged.mcscan.bed` (55,437 genes) +
  `siscowet_purged.mcscan.bed` (59,968 genes), un-sanitizing contig names against the FASTA
  `.fai` so BED chromosomes match the assemblies exactly (verified: 0 mismatches). `config.json`
  now declares `lean_purged` + `siscowet_purged` assemblies (FASTAs streamed from Gannet,
  `.fai` served locally), a `SyntenyTrack` (`MCScanAnchorsAdapter`), and a gene FeatureTrack per
  ecotype. Open via JBrowse's *Linear synteny view* selecting the two ecotype assemblies.
  - Remaining Phase 2 polish: ship a pre-built Linear Synteny **saved session** so the browser
    link opens straight into the lean-vs-siscowet ribbon view; optionally add `ref↔lean` /
    `ref↔sisco` synteny tracks the same way.
- **Phase 3:** breakpoint/rearrangement track + polish (colors, feature-detail formatting, GO links out).

## 5. Open decisions

  ecotype assembly (needs Path B assemblies). Recommend single reference-projected for Phase 1.
- How much GO detail to embed in feature attributes vs. link out (e.g., to the annotation table
  on the landing page).
- Whether to host the purged ecotype FASTAs on Gannet now (needed for Path B) or defer.
