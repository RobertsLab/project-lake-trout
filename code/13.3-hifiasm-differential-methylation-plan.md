# 13.3 hifiasm differential methylation plan

## Goal

Generate a differential methylation workflow for the ecotype-specific hifiasm assemblies while reusing the repository's existing PacBio alignment, methylation-calling, and DMR analysis patterns as much as possible.

## Existing codebase pieces to reuse

- `code/13.1-hifiasm-genome-assembly-lean.Rmd` and `code/13.1-hifiasm-genome-assembly-siscowet.Rmd` generate the primary contig FASTA files that should be treated as the new assembly references.
- `code/13.2-genome-assembly-comparisons.Rmd` already compares Flye and hifiasm assemblies with QUAST and can be used to justify using the primary hifiasm contigs for downstream methylation work.
- `code/04-pacbio/align_hifi_pbmm2.py` provides the current pattern for aligning PacBio HiFi reads with `pbmm2`.
- `code/10-mCG-call.Rmd` defines the current `modkit pileup` → `bedGraph`/`bigWig` methylation-calling workflow.
- `code/14-diff-meth.py` and `code/14-diff-meth.Rmd` define the current statistical workflow for differential methylation, including CpG merging, Mann-Whitney testing, FDR correction, and DMR aggregation.

## Key constraint

The current differential methylation code assumes all samples share the same coordinate system because CpGs are merged by `chrom:pos` in `code/14-diff-meth.py`. That assumption does not hold once lean and siscowet reads are analyzed against separate hifiasm assemblies, so coordinate harmonization has to be added before any cross-ecotype DMR test.

## Plan of work

### 1. Freeze the assembly inputs

- Use the primary contig FASTA outputs from:
  - `output/13.1-hifiasm-genome-assembly-lean/pb-hifiasm-lean-assembly.fa`
  - `output/13.1-hifiasm-genome-assembly-siscowet/pb-hifiasm-siscowet-assembly.fa`
- Record the corresponding QUAST summary from `code/13.2-genome-assembly-comparisons.Rmd` so the chosen assembly set is explicit before methylation work starts.
- Keep haplotype FASTA files out of the first-pass analysis unless a later QC step shows the primary contigs are insufficient.

### 2. Re-align PacBio reads to the matching hifiasm assembly

- Reuse `code/04-pacbio/align_hifi_pbmm2.py` instead of creating a separate alignment workflow.
- Run lean samples (`bc2041`, `bc2068`, `bc2069`, `bc2070`) against the lean hifiasm primary contigs.
- Run siscowet samples (`bc2071`, `bc2072`, `bc2073`, `bc2096`) against the siscowet hifiasm primary contigs.
- Write the resulting BAMs and logs to a dedicated analysis folder so they stay separate from the current reference-genome alignments, e.g. `analyses/13.3-hifiasm-diff-meth/alignments/{lean,siscowet}/`.

### 3. Re-run methylation calling on the hifiasm alignments

- Follow the same pattern used in `code/10-mCG-call.Rmd`:
  1. run `modkit pileup --cpg --combine-strands`
  2. convert `bedMethyl` output to percent-methylation bedGraph
  3. generate bigWig tracks for browser/QC use
- Keep outputs grouped by ecotype assembly, for example:
  - `analyses/13.3-hifiasm-diff-meth/methylation/lean/`
  - `analyses/13.3-hifiasm-diff-meth/methylation/siscowet/`
- Preserve the current coverage filter strategy by generating `cov10`-style bedGraph files for downstream testing.

### 4. Build a shared coordinate set between assemblies

- Add a whole-assembly alignment step between the lean and siscowet hifiasm primary contigs to identify one-to-one homologous blocks.
- Use that alignment to derive a mapping table that links:
  - lean contig + position
  - siscowet contig + position
  - shared block identifier/orientation
- Restrict downstream differential testing to CpGs that fall inside confidently aligned blocks so methylation is compared between homologous loci instead of raw assembly coordinates.
- Treat this mapping table as a first-class intermediate file because it is the new dependency that the current `14-diff-meth.py` workflow does not need on the common reference genome.

### 5. Adapt the existing DMC/DMR workflow to the harmonized loci

- Reuse the current statistical choices from `code/14-diff-meth.py` unless QC indicates they need revision:
  - minimum 3 samples per group with data
  - Mann-Whitney U test
  - Benjamini-Hochberg correction
  - 15% methylation-difference threshold
  - DMR merge distance of 250 bp
  - minimum 3 CpGs per DMR
- Modify the input stage so the methylation matrix is built from homologous lean/siscowet CpG pairs rather than direct `chrom:pos` matches.
- Save both the harmonized CpG table and the downstream DMC/DMR result tables under `analyses/13.3-hifiasm-diff-meth/`.

### 6. Annotate and compare results

- Annotate DMRs against the matching hifiasm assembly coordinates first.
- If gene annotations are only available on the NCBI reference, add an intermediate lift/transfer step rather than mixing annotation coordinates directly with hifiasm coordinates.
- Compare the hifiasm-based DMC/DMR set back to the existing reference-based results in `analyses/14-diff-meth/` to determine which signals are stable and which are reference-dependent.

### 7. QC and deliverables

- QC checks should mirror the current repository workflow:
  - alignment counts and BAM integrity
  - number of CpGs recovered per sample after coverage filtering
  - number of homologous blocks/CpGs retained after coordinate harmonization
  - DMC and DMR counts by direction
- Deliverables for the first complete pass:
  - ecotype-specific hifiasm BAMs
  - per-sample methylation bedGraph/bigWig files
  - assembly-to-assembly homologous block map
  - harmonized CpG matrix
  - DMC and DMR result tables
  - an R Markdown summary, analogous to `code/14-diff-meth.Rmd`, for visualization and interpretation

## Recommended implementation order

1. Confirm the primary hifiasm contigs to use from the existing 13.1/13.2 outputs.
2. Re-align reads with the existing `pbmm2` workflow.
3. Re-run `modkit pileup` and regenerate methylation bedGraph/bigWig files on the hifiasm assemblies.
4. Generate the assembly-to-assembly coordinate map.
5. Refactor the current differential methylation script so it can consume harmonized CpG pairs.
6. Render a new hifiasm-specific differential methylation report once the result tables are stable.
